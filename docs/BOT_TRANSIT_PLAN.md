# 让 bot 像玩家一样跨大陆通行 —— 实施规划

> 目标：bot 能像真实玩家那样，在 v83 的各大陆之间**坐船/坐车/坐飞机/坐电梯**往来，
> 而不是走到一半没路了就裸 warp。
>
> 本文档只做规划，不含实现。完整交通数据见 `TRANSPORT_ROUTES.md`。

## 一、现状：卡在哪

### 1.1 三道独立的闸门

bot 想从 A 大陆到 B 大陆，要连过三道闸门，**任何一道没开就到不了**：

| 闸门 | 代码位置 | 现状 |
|:--:|---|---|
| ① **世界图有没有这条边** | `GCWorldGraph.neighbors()` | 只有传送门 + 出租车 + `BotScriptedWarp`；**船/车/飞机/电梯全都没有边** |
| ② **目的大陆在不在白名单** | `TrainingRegions.ALLOWED` | 只有**维多利亚岛、天空之城、玩具城**；神木村、阿里安特、武陵等全在名单外 |
| ③ **内容有没有被版本剪掉** | `MapleVersionManager.version = 55` | v83 的时间神殿(72)、诺特勒斯(62)、圣地(73) 被误剪 |

### 1.2 第四道隐性闸门：看门狗

**这是最容易被低估的一层。** 三道闸门全开后，还会撞上 `GCTravel` 的看门狗
——它们的设计前提是"一跳应在 90 秒内走完"：

| 看门狗 | 阈值 | 对交通的含义 |
|---|--:|---|
| `HOP_STUCK_MS` | 12s | 站着不动 12s 就判定"卡死"，直接 warp 掉 |
| `SOFT_LOCK_MS` | 20s | 在 400px 范围内待 20s 判定"原地打转" |
| `HOP_MAX_MS` | 90s | 每跳绝对上限，超时强制 warp |

**船的周期是 4(关门)+5(开船)+10(航程) = 19 分钟量级。**
出租车等 2–6 秒能借 `settled` 快速路径（L292-298 提前 return）蒙混过去，
但**等船必然被三个看门狗全部判死**，然后触发裸 warp —— 恰好是要避免的行为。

> **看门狗豁免不是"顺手做一下"，而是接船能否成立的前提。**

## 二、能力分层

分 5 层，**每层独立可用、独立可测**。上层依赖下层，但下层做完就有价值。

```
L5  编排层    多段行程串联（出租车→船→火车）、返程、超时兜底
     ↑
L4  等待层    看门狗豁免 + 轮询 em.getProperty("entry") 等开门
     ↑
L3  载具层    船/车/飞机 作为边接入世界图
     ↑
L2  直达层    NPC 付费直达 / 道具门 / 电梯（无时刻表）
     ↑
L1  地基层    版本阈值 55→83、白名单扩容、NPC id 修正
```

---

### L1 · 地基层（改配置，零逻辑）

**L1.1 版本阈值 `55 → 83`**

`MapleVersionManager.version` 是硬编码 `public static int version = 55`，无人修改；
服务器真实版本 v83（`ServerConstants.VERSION = 83`）。

- **收益**：时间神殿(72)、诺特勒斯(62)、圣地(73)、塔拉森林时间门(83)、马来西亚(77) 纳入
- **风险**：这些地图此前从未被 bot 访问过，需确认无异常（怪等级、地形、VR 边界）
- **成本**：改一个数字
- **建议**：先用 `!gcmove route` 抽样验证几张新开放的图能寻路，再改

**L1.2 白名单扩容**

`TrainingRegions.ALLOWED` 目前 4 个窗口。按大陆补：

| 窗口 | 大陆 | 有怪图 | 前置 |
|---|---|--:|---|
| `{230000000, 240000000}` | 水世界 | 23 | 无（顺带合法化现有绕道） |
| `{240000000, 250000000}` | 神木村 | 74 | 需先接 `Cabin` 小屋 |
| `{250000000, 252000000}` | 武陵 | 32 | 需先接 `Hak` |
| `{260000000, 262000000}` | 阿里安特 | 39 | 需先接 `Genie` 精灵 |
| `{700000000, 710000000}` | 中国·上海 | 40 | 需先接上海飞机 |

> **顺序**：只加白名单不接交通 = bot 依然到不了，但 `TrainingMapFinder`
> 会白扫一遍（浪费）。建议与对应交通同步开。

**L1.3 NPC id 修正（不阻塞）**

`GCTaxi.npcPos()` 走 `map.getNPCById()`（WZ 实例），**必须用 WZ 里的 id**。
魔法密林线售票 `1032007` / 检票 `1032009`（船员普林）是两个人；
现有 `GCTaxi.VICTORIA_CABS` 用的是**售票** id（`1012000` 射手村中巴）。

- 既有行为能跑（售票 NPC 也在城里），但不严谨
- 建议后续核对，不阻塞本次

### L2 · 直达层（无时刻表，性价比最高）

**为什么先做这层**：NPC 收钱直接 `cm.warp()` 或道具门直接放行，
**不需要等开门**，因此**完全不需要 L4 的看门狗豁免**。

| 航线 | 触发方式 | 起点 | 终点 | 条件 | 白名单需补 |
|---|---|---|---|---|---|
| 天空之城 ⇄ 武陵（鲸 `Hak`） | NPC `2090005` 鹤 | `200000141` | `250000100` | 1500 金币 | 武陵 |
| 武陵 ⇄ 药草镇 | NPC `2090005` 鹤 | `250000100` | `251000000` | 500 金币 | 武陵 |
| 勇士部落 ⇄ 上海外滩 | NPC `9310000`/`9310013` 驾驶员洪 | `102000000` | `701000000` | 2000 金币 | 中国·上海 |
| 神木村西境 ⇄ 魔法密林北郊 | 道具门 `minar_elli.js` | `240010100` | `101010000` | `4031346` 种子 | 神木村 |
| 诺特勒斯 ⇄ 欧米伽 | 道具门 `enter_earth00/01.js` | `120000101` | `221000300` | `4031890` 卡 | —（两端已开） |
| 太阳塔 → 艾琳营地 | 道具门 `move_elin.js` | `222020400` | `300000100` | **免道具** | 艾琳森林 |
| 太阳塔 2F ⇄ 99F | 电梯 `Elevator` | `222020100` | `222020200` | 免票，~60s | —（同在玩具城） |

**实现方式**：复用现成的 `BotScriptedWarp` —— 它本就是为
"传送门图看不到的脚本 warp"设计的，这些完全符合定义。

```java
new WarpEdge(200000141, "h000", 250000100, 0),   // Hak 天空之城 → 武陵
new WarpEdge(250000100, "h000", 200000141, 0),   // Hak 武陵 → 天空之城
new WarpEdge(222020100, "up00", 222020200, 0),   // 电梯 上
new WarpEdge(222020200, "down00", 222020100, 1), // 电梯 下
```

**⚠ 两个新查到的约束（原规划漏了）**

1. **`Hak` 有并发上限**：走 `em.startInstance()`，`EventManager.maxLobbys = 8`。
   占满时 NPC 拒绝："We are currently taking requests from too many maplers..."
   → **多个 bot 同时坐 Hak 会失败**，需要重试或排队（详见 §四）
2. **电梯两端无 NPC**：`222020100` / `222020200` 都没有 NPC，
   只能按坐标走到门口再触发，不能复用 `GCTaxi.npcPos()` 的按 NPC 定位逻辑

**建议首批只做 Hak 一条验证闭环**（天空之城 ⇄ 武陵）：
起点 `200000141` 在天空之城（已连通区），1 条边 + 1 个白名单窗口，
就能让 bot 第一次走出原大陆。

### L3 · 载具层（船/车/飞机接入世界图）

**结构性建议：把 `GCTaxi` 泛化成"交通边"表。**

船/车/飞机与出租车**结构同构**：都是「走到某个点 → 停留 → warp 到目的地图」。
差别只在"停留多久"由什么决定：

| 类型 | 停留时长 | 决定方 |
|---|---|---|
| 出租车 | 2–6s（已实现） | 固定随机 |
| 电梯 | ~60s | 事件 `beginTime` |
| 船/车/飞机 | 0–19min | **外部事件 `entry` 属性** |

```java
record TransitEdge(int fromMapId, int npcId, int toMapId, String eventName) {}
```

- `eventName == null` → 出租车，固定 2–6s 停留
- `eventName != null` → 载具，轮询 `em.getProperty("entry")` 等开门
- `GCWorldGraph.neighbors()` 已会把 taxi 边并进 BFS，**加一张表即可，路由零改动**

**四条载具落点数据**（已核实，见 `TRANSPORT_ROUTES.md` §二②）：

| 载具 | 候车室（去 / 回） | 检票 NPC | 到达站 | 航程 |
|---|---|---|---|--:|
| `Boats` 船 | `101000301` / `200000112` | `1032009` 船员普林 / `2012002` 阿霖 | `200000100` 天空之城售票处 / `101000300` 魔法密林码头 | 10min |
| `Trains` 火车 | `200000122` / `220000111` | `2041001` 俄林 | `220000100` 玩具城售票处 / `200000100` 天空之城售票处 | 5min |
| `Cabin` 小屋 | `200000132` / `240000111` | `2012022` 帕拉斯 / `2082002` 哈利 | `240000110` 神木村码头 / `200000100` 天空之城售票处 | 5min |
| `Genie` 精灵 | `200000152` / `260000110` | `2012024` 意奈特 / `2102001` 斯林 | `260000100` 阿里安特升降场 / `200000100` 天空之城售票处 | 5min |

**⚠ Cabin 下船点陷阱**：`Cabin` 的到达是 `240000110`，但**该图无任何传送门出边（死路）**，
能走进神木村的是 `240000100`。接入时**终点要填 `240000100`**，
否则 bot 下了船就卡死在死路。

### L4 · 等待层（看门狗豁免 + 等开门）

**这是 L3 能否成立的前提，建议与 L3 同批做。**

**L4.1 轮询 `entry`，不要自算时刻**

```java
EventManager em = bot.getMap().getChannelServer()
                     .getEventSM().getEventManager("Boats");
boolean boarding = "true".equals(em.getProperty("entry"));
```

（已用编译探针验证插件能直接引用 `EventManager`，无需 client。）

**必须轮询的原因**：所有时刻过 `em.getTransportationTime()` → `World.travelRate`
（数据库配置），且 `GameConfig.getWorldFloat()` 在配置缺失时返回 **0**，
会让全部运输时间归零。**不能硬编码 15 分钟。**

**L4.2 看门狗豁免**

给"正在等船"开一个豁免通道，三条看门狗都要绕：

| 看门狗 | 豁免方式 |
|---|---|
| `HOP_STUCK_MS` 12s | 等船时不进入进度判定 |
| `SOFT_LOCK_MS` 20s | 同上 |
| `HOP_MAX_MS` 90s | 按载具周期放大到 ~25min，并加独立兜底 |

**建议做法**：在 `Trip` 上加 `waitingForTransit` 状态位，
三个看门狗在 `approachAndAct()` 里看到该位置就跳过判定。
同时给等待本身加**独立的、远大于船周期的兜底上限**（如 25 分钟），
避免事件管理器挂掉时 bot 永久滞留。

**同时同步放大 `TrainingBot.TRAVEL_TIMEOUT_MS`（120s）**，
否则 bot 大脑会先于 GCTravel 放弃。

---

### L5 · 编排层（多段行程）

L1–L4 就位后，bot 才能跑出真实玩家那样的多段行程，例如
「明珠港 →(出租)→ 魔法密林 →(船)→ 天空之城 →(火车)→ 玩具城」。

这层主要是**验证和收尾**：
- 多段行程中，每段白名单、载具、等待是否正确衔接
- 返程链路是否对称（`Boats`/`Trains`/`Cabin`/`Genie` 都是双向，要都接）
- 观察日志，确认没有 bot 卡在候车室或下船死路

## 三、推荐实施顺序

| 步骤 | 内容 | 层 | 成本 | 验证方式 |
|:--:|---|---|:--:|---|
| **1** | `version` 55→83 + 抽样验证新开放地图 | L1 | 极低 | `!gcmove route` 到 `270000100` |
| **2** | 接 **Hak**（天空之城⇄武陵）+ 白名单加**武陵** | L2 | 低 | bot 从天空之城走到武陵 |
| **3** | 接 **电梯**（太阳塔 2F⇄99F） | L2 | 低 | bot 能从玩具城本岛到韩国民俗村 |
| **4** | 接**上海飞机**（中文专属）+ 白名单加**中国·上海** | L2 | 低 | bot 从勇士部落到上海外滩 |
| **5** | 泛化 `GCTaxi` → `TransitEdge`（结构改造） | L3 | 中 | 出租车行为不变（回归） |
| **6** | 接 **Boats** + L4 看门狗豁免 | L3+L4 | 高 | bot 从魔法密林坐船到天空之城 |
| **7** | 接 **Trains**（天空之城⇄玩具城，复用 L4） | L3 | 低 | 天空之城⇄玩具城直达 |
| **8** | 接 **Cabin / Genie** + 白名单加**神木村、阿里安特** | L3 | 低 | 神木村、阿里安特可达 |
| **9** | L5 多段行程联调 + 日志观察 | L5 | 中 | 长行程成功率 |

**关键路径**：步骤 6（Boats + L4）是唯一高成本项，
也是唯一能连通**维多利亚岛**（bot 人口最多，236 张练级图）与外界的通路。
**步骤 1–4 都能在它之前独立完成并产生价值。**

## 四、风险与注意事项

| 风险 | 说明 | 缓解 |
|---|---|---|
| **版本阈值改动面太大** | 55→83 同时放开大量未验证地图 | 先抽样验证；必要时分模块门控而非全局改 |
| **白名单扩容导致扫描变慢** | `TrainingMapFinder` 会对更多图 BFS + 读怪等级 | 与交通同步开，避免空扫 |
| **`Hak` 并发上限 8** | `em.startInstance()`，`maxLobbys=8`；占满时 NPC 拒绝 | bot 需重试/排队；或错峰（随机延迟后重试） |
| **候车室被判定为卡死** | 即使有豁免，边界情况仍可能误判 | 加独立兜底上限 + 日志可观测 |
| **Cabin 下船死路** | `240000110` 无出边 | 终点填 `240000100` |
| **电梯两端无 NPC** | `222020100`/`222020200` 都没有 NPC | 不能复用按 NPC 定位，需按坐标/传送门名 |
| **多个 bot 挤同一候车室** | 视觉上叠在一起 | 后续可考虑散布到候车室不同位置 |
| **船票/金币** | 真实玩家要买票 | bot 无经济系统（装饰品），**不做票务**，沿用出租车"纯移动"定位 |
| **NPC 不在图上** | 地图未加载时 `getNPCById` 返回 null | 已有退化逻辑（直接 warp），保留 |

## 五、明确不做

| 项 | 理由 |
|---|---|
| 票务 / 金币消耗 | bot 是装饰品，无经济系统（与出租车一致） |
| 回城卷 | 按范围要求不纳入 |
| 英语村 | 未开放内容，无入口 |
| 新手村单向路 | 只出不进，让 bot 进去会永久滞留 |
| 钓鱼场 / 婚庆 / PQ 副本 | 非交通节点 |
| 万能传送 | GM 菜单，玩家不可用 |
