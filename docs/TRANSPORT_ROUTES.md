### 版本基准与插件的内容裁剪

| 项 | 值 | 出处 |
|---|---|---|
| **服务器真实版本** | **v83** | `ServerConstants.VERSION = 83` |
| 插件门控阈值 | `version = 55` | `MapleVersionManager.version`（硬编码，无人修改） |

`portal_versions.yaml` 里的数字含义是"该内容在哪个**客户端版本**引入"，
**不是服务器版本**。插件用 `version=55` 把 >55 的内容全部剪掉，
于是 v83 本该开放的内容被误剪：

| 地图 | 引入版本 | v83 实际 | 插件(55) 判定 | 影响 |
|---|--:|:--:|:--:|---|
| `270000000` 时间神殿 | 72 | ✓ 开放 | ✗ 剪掉 | 变龙飞行整条链被插件判为不可达 |
| `120000000` 诺特勒斯 | 62 | ✓ 开放 | ✗ 剪掉 | 传送卡门所属城镇被剪 |
| `130000000` 圣地 | 73 | ✓ 开放 | ✗ 剪掉 | 女皇之路（含 `130000210` 天空渡口） |
| `240070000` 塔拉森林时间门 | 83 | ✓ 开放 | ✗ 剪掉 | 神木村时间之门 |
| `551000100` 马来西亚 | 77 | ✓ 开放 | ✗ 剪掉 | 旅行社马来西亚线落点 |
| `103040000` 废都广场 | 83 | ✓ 开放 | ✗ 剪掉 | — |

> **本文档按真实 v83 描述世界**；插件 bot 的实际可达范围受 `version=55` 限制，
> 会比这里更小。若将来把 `MapleVersionManager.version` 改成 83，
> 时间神殿、诺特勒斯、圣地 等会自动对 bot 开放。

> **重要修正**：变龙飞行去时间神殿（⑥）虽然是 WZ 里真实存在的链路，
> 这两条在**真实 v83 服务器上可用**；但插件用 `version=55` 剪掉了
> `270000000`(72) 和 `120000000`(62)，所以 **bot 目前走不了这两条**。
> 详见 §1「版本基准」——把 `MapleVersionManager.version` 改成 83 即可解锁。

### ⑥ 变龙飞行 → 时间神殿（最特殊）

入口**在神木村**，链路跨 1 个 NPC + 3 个 portal 脚本 + 1 个变身道具：

```
去程  神木村站台 240000110
      └ NPC 2082003（克鲁巴）
         ├ useItem(2210016)  变身为 Mini Draco
         └ warp(200090500)   "前往时间神殿"（飞行图）
            └ 终点踏门 in00 → templeenter.js
               ├ cancelItem(2210016)  解除变身
               └ warp(270000100)      抵达时间神殿

返程  270000100 门 out00 → outTemple.js
      ├ useItem(2210016)  重新变身
      └ warp(200090510)   "前往神木村"（可再进神殿）

放弃  飞行图 200090500/200090510 的 down00~down36（37 个门）
      └ undodraco.js → 退回神木村 240000110
```

> **传送门图里查不到的原因**：三张飞行图的所有门 `tm` 都是 `999999999`（空门），
> 方向全由 portal 脚本决定。`GCWorldGraph` 既跳过 scripted 门、也无视 `999999999`。
>
> **注意**：入口 NPC 在 `240000110`，而那正是 **Cabin 下船的死路**——
> 下船后得退回 `240000100` 才能进村，但要去时间神殿**得再回到 `240000110`**。

### ⑧ 中国·上海 —— 上海外滩，付费飞机直达

`String.wz` 与英文 handbook **均无 70 段地名**，但 `scripts-zh-CN/`

且各自只有一个 `pn=out00` 的**出口门**，全 WZ 扫描确认**没有任何传送门指向它们**。

| 钓鱼场 | 出口通往 |

### 三个硬性约束

1. **NPC id 以 WZ 为准，不是脚本文件名。**
   售票与检票是两个 NPC（魔法密林线：售票 `1032007` / 检票 `1032009`）。
   `GCTaxi.npcPos()` 走 `map.getNPCById()`（WZ 实例），照抄脚本 id 会永远返回 `null`。

2. **时刻表是运行时配置，不能硬编码。**
   所有时间过 `em.getTransportationTime()` → `World.travelRate`（数据库配置）。
   `GameConfig.getWorldFloat()` 在配置缺失时返回 **0**，会让全部运输时间归零。
   必须**轮询 `em.getProperty("entry")`**，不可自算时刻。

3. **等待会撞飞 GCTravel 的三个看门狗。**
   `HOP_STUCK_MS=12s`、`SOFT_LOCK_MS=20s`、`HOP_MAX_MS=90s`；而船周期 4+5+10 = **19 分钟**。
   出租车等 2–6s 能借 `settled` 快速路径蒙混过去；等船则必然被判"卡死"触发裸 warp——
   恰好是要避免的行为。**看门狗豁免是接船能否成立的前提。**
