# 各职业各转职阶段：bot 技能覆盖记录

> 结论性档案，回应「各职业各转职阶段、对外可见的 buff/攻击技能是否都实现了」。
> 数据源：宿主 GMS083 `wz/Skill.wz/{job}.img.xml` + `wz-zh-CN/String.wz/Skill.img.xml`（冒险家 5 系，
> job≥100 共 316 个技能节点）。实现源：`BotAttackConfig`（攻击）、`BotBuffConfig`（增益）、
> `BotSummonSystem`（召唤实体）。

## 1. 覆盖原则（**不是**「逐技能全量复刻」）

bot 是**装饰性**实体，只呈现「玩家一眼能看出」的技能。因此覆盖是**主动选择子集**，不是缺漏：

| 类别 | 是否实现 | 说明 |
|---|---|---|
| 主动攻击（每个终职的单体 + AoE + 终极） | ✅ 每职都有 | 见 §2 |
| 招牌增益（各职 booster / 全体 / 4 转标志技） | ✅ 已补齐 | 见 §3 |
| 召唤兽（实体：生成/服务端驱动移动+攻击/消失） | ✅ 11 只 | 见 §4 |
| **纯被动**（坐骑、终极攻击被动、格挡、抗性、专精…） | ⛔ 有意不做 | 无自身施法动作可呈现 |
| **武器变体 booster**（快速斧/钝器/矛…每系只留一个代表） | ⛔ 有意合并 | 视觉几乎无差别 |
| **非自身增益**（烟雾弹=地面领域、心灵控制=对怪、暗器伤人=武器附魔…） | ⛔ 有意不做 | 施在别处，非自身光环 |
| **低阶小攻击**（1-2 转被后续技取代的过渡技） | ⛔ 有意省略 | 已被该职主攻取代 |

## 3. 增益（`BotBuffConfig`）

按职业谱系逐级累加 `put(Job.X, …)`。本轮**新增**：

- 4 转系统性：**稳如泰山**（英雄/圣骑/黑骑 STANCE）、**勇士的意志**（冒险家全部 11 个 4 转；冲锋队长的 host 常量名为 `Buccaneer.PIRATES_RAGE = 5121008`）。
- 1 转：疾驰（海盗 5001005）。
- 2 转：轻羽鞋（火枪手 5201005）。
- 3 转：转化术（独行客 4211001）、敛财术（4211003）、橡木伪装（拳手 5101007）。
- 4 转：击退箭（神射 3121007）、致盲箭（弩神 3221006）、超级变身（冲锋队长 5121003）、极速领域（船长 5221010）。

**有意不纳入**（非自身施法增益，纳入会表现为错误施法）：恢复术/守护之神（被动）、武器用毒液（武器附魔）、灵魂祝福（召唤兽被动）、心灵控制（对怪）、烟雾弹（地面领域）、战舰（坐骑）、隐身术（会隐藏 bot）。

**召唤类从增益表移除**：章鱼炮台（5211001）由 `BotBuffConfig` 的 buff 改为 `BotSummonSystem` 的真实召唤实体。

**渲染说明**：`稳如泰山`/`勇士的意志`/`击退箭`/`致盲箭`/`疾驰`/快速移动类 等在宿主 `StatEffect` 有对应 statup，会广播持久光环；`超级变身`（morph）等少数无 statup 的则只播**施法动画**——这与真实客户端的表现一致（变身是 morph，不在 foreignBuff 里）。

**光环封包必须按技能族分流（重要）**：v83 客户端对 `GIVE_FOREIGN_BUFF` 的解码**并非只有一种**。宿主 `StatEffect.applyTo` 自己就把三个技能族走**扩展帧**，其余才走通用帧：

| 族 | 判据（宿主同名方法） | 技能 | 宿主/插件应发的包 |
|---|---|---|---|
| 疾驰 | `isDash()` | 5001005 / 15001003 / 1014 / 1001015 | `giveForeignPirateBuff` |
| 极速领域 | `isInfusion()` | 5121009 / 15111005 / 5221010（宿主常量误名为 `Corsair.HEROS_WILL`，实为极速领域） | `giveForeignPirateBuff` |
| 元素剑 | `isWkCharge()`（statup 含 `WK_CHARGE`） | 烈焰/寒冰/雷电/圣灵之剑（1211003/1211004/1211005/1221003 等） | `giveForeignWKChargeEffect` |

用通用短帧顶替扩展帧时，客户端会**读过头**（报「数据过短」并崩溃）——`BotBuffEffects.broadcastAura` 现已按上表分流；`BotBuffEffectsLayoutTest` 把每个技能 id 与宿主 `StatEffect` 的判据逐一对表（宿主源码不在旁边时自动跳过）。

## 4. 召唤（`BotSummonSystem`）

11 只真实地图实体。**真玩家自己的召唤兽**由该玩家的客户端自行模拟并上行 `MOVE_SUMMON`（宿主 `MoveSummonHandler` 只把它回显广播）；
而客户端**只驱动"本机玩家自己"的召唤兽**——别人的（含 bot 的）召唤兽只按服务端下发的 `MOVE_SUMMON` 帧渲染。
bot 无客户端，故服务端必须**代它模拟**：**生成**、每 tick **计算跟随/环绕位置并广播 `MOVE_SUMMON`**（与宠物 `MOVE_PET` 同范式）、
主人换图时**重生成**、对攻击型**发射 `SUMMON_ATTACK`**、**移除**。

| 召唤兽 | 技能 | 服务端移动 | 服务端攻击 |
|---|---|---|---|
| 银鹰/金鹰/火凤凰/冰凤凰 | 3111005/3211005/3121006/3221005 | 环绕（服务端驱动） | ✅ |
| 冰破魔兽/火魔兽 | 2121005/2221005 | 跟随（服务端驱动） | ✅ |
| 圣龙/强化圣龙 | 2311006/2321003 | 环绕/跟随（服务端驱动） | ✅ |
| 章鱼炮台/超级章鱼炮台 | 5211001/5220002 | **静止**（永不下发移动帧） | ✅ |
| 灵魂助力（黑骑士） | 1321007 | 跟随（服务端驱动） | ⛔（辅助） |

**有意不实现**：
- **替身术木偶**（3111002/3211002）：唯一作用是拉怪仇恨，而宿主对木偶仇恨的判定要求 `BuffStat.PUPPET`
  （`Monster.isCharacterPuppetInVicinity` 读 `getBuffEffect(BuffStat.PUPPET)`）；本插件不注册任何 buff，
  因此木偶会变成起不到作用的装饰——宁可不做，也不做半个错的。
- **持久伴侣（companion）不授予召唤**：召唤需先教会技能，而伴侣会把技能/SP 落库，登记一个其 SP 加点从未分配的
  技能会永久污染 `getUsedSp` 与技能书 SP。仅**环境（非持久）bot** 获得召唤。
- **主人瞬移（> `snap_distance`）不做"移除+重生成"**：召唤兽直接把实体置于目标位并补一帧同点移动帧，
  不做宠物式的重生成——召唤兽的移动帧本身就携带新位置，重生成除了多两个包没有额外收益。

## 5. 校验

- `BotBuffConfigSourceTest`：注册的每个常量必须解析到 `Skill.wz` 中真实存在的 id；同一职业不得重复注册（EnumMap 覆盖陷阱）。
- `BotSummonTableTest` / `BotSummonConfigTest` / `BotSummonMoveRuleTest` / `BotSummonMovePacketTest`：炮台 **STATIONARY 恒不被移动**（`shouldReposition`）；
  `MOVE_SUMMON` 帧逐字节锚定；跟随/环绕目标点数学；谱系解析；召唤选择器。
- 全量 `mvn test`：**1259 通过，0 失败**。
