# Bot 社交关键词补充方案（国人常见：问候 / 调侃 / 夸奖 / 大笑 / 认同 / 告别 …）

> 状态：**人格层（§5B）已实现并合入**；**关键词需（§4 大批量）与社交意图分类器仍为待实施方案**。
> 目标：让 bot 更懂国内玩家的日常用语——**听懂**（识别常见问候、调侃、夸奖、大笑、认同、告别等意图）并**回得上**（有对应的高频口语台词），中英双语关键词与台词同时生效。
> 范围：以 `SocialBot` 为主，兼顾 `TrainingBot` / `FollowerBot` 的问候与告别；不含游戏类 bot（骰子/21点/游戏厅）与商人。

## 实现摘要（§5B 人格层，已合入）

- 新增 `Persona`（`TEASE/SARCASTIC/HYPE/CASUAL/CHILL/FRIENDLY`，按角色 id 稳定分派，默认偏喷子）+ `SocialPersonaConfig`（键 `solomapling.social.persona`=`cheeky|chill|off`、`solomapling.social.tease-chance`，默认 cheeky/65%）。
- `SocialBot`：`pickResponseCategory` 改为**人格驱动**——脸皮厚人格常态出 `Banter`，仅"更毒人格 + 高出玩家≥15级 + 冷却"才升级 `SmackTalk`；`appendGreeting` 变为**问候+补刀**；LLM 关闭时的兜底回复也走人格。
- `SocialLlmPromptBuilder`：系统提示词按人格注入"嘴欠"人设与红线（只损游戏里的事）；`SocialLlmService` 传入该 bot 的人格。
- 新增台词节点 `Banter`（中英各 48 行，轻嘴欠日常池）；`SmackTalk` 保留为高等级专属重口池。
- 测试 `SocialPersonaTest`（6 项）：分布偏嘴但不单一、同 id 人格稳定、harsh⊂cheeky、chill 变软、Banter 中英皆在、默认档为嘴欠。**854 项测试全绿**。

## 0. 结论先行

1. **现状**：bot 的"选项菜单关键词"只覆盖功能意图（组队/练级/跟随/告辞等），**没有"社交意图"层**——问候、调侃、夸奖、大笑、认同、道歉、感谢、惊叹这些国内玩家张口就来的话，要么被当成"任意搭话"回一句 `Greeting`（如 "嘿。"），要么走 LLM 自由发挥（关了 LLM 就完全没有对应台词）。
2. **因此本方案要加两层**：
   - **识别层**：新增一个"社交意图"匹配器（问候 / 夸奖 / 调侃 / 大笑 / 认同 / 道歉 / 感谢 / 鼓励 / 惊叹 / 告别 / 求带 …），把玩家原话归类到一个意图。
   - **台词层**：为每个意图新增 YAML 台词节点（`GreetingCommon` / `Praise` / `Banter` / `Cheer` / `Wow` / `Laugh` / `Agree` / `Apology` / `Thanks` 等），中英各一套高频口语。
3. **大批量收录**：本版把关键词扩到**约 400+ 条**（含网络缩写/颜文字/方言/谐音），覆盖国内玩家日常交流的高频表达。
4. **最大坑**：现有匹配是 **`contains` 子串包含 + 按选项顺序**。单个字符（"哈"/"牛"/"菜"/"带"）会误伤半句聊天。所以新关键词一律 **≥2 个汉字或整词/等值**（短符号/缩写走 exact），并定义**固定的意图优先级**（先判断更具体的，再看泛化的）。
5. 关键词仍沿用现有**中英合并**机制（英文关键词 + `BotMessages-zh-CN.yaml` 别名 + 中文标签自动派生），**不破坏**既有的"窄匹配"纪律与回归测试（`MenuKeywordRegressionTest`）。

## 1. 现状机制（为什么这样设计）

### 1.1 三条触发入口

| 入口 | 触发 | 归谁处理 |
|---|---|---|
| 点名 | 地图聊天**含 bot 名** | `Dispatcher` → `displayCommands` 弹菜单 |
| 组队广播 | 同队同图、不打名字 | `deliverToPartyBots` → 各 bot `offerKeyword` |
| **定向频道** | 私聊/组队/好友/公会/联盟 | `DirectChatBridge` → `onDirectChat` |
| 招募喊话 | 地图喊话含 `party/team/join/group/组队/一起` | `BotRecruitManager.broadcastRecruit` |

### 1.2 匹配与数据落点

- **匹配器**：`BotOptionMenu.match()` —— 先认数字 `"1"/"2"…`，再对每个选项的关键词做 `content.trim().toLowerCase().contains(kw)`，**按选项顺序**首个命中即停。
- **关键词来源**（`BotMessages.keywords()`，三者**合并**）：
  1. Java 里手写的**英文**关键词数组（权威、刻意窄）；
  2. `BotMessages-<lang>.yaml` 的 `menu.<prefix>.<suffix>.keywords` 别名（**中文加词就加这里**）；
  3. 本地化标签文本**按标点切词派生**——但**仅非拉丁文**（中文标签会整段成为关键词；英文标签不派生，避免 "how" 这类贪心词）。
- **台词来源**：`BotDialoguePack/<Type>Dialogue.yaml` 与 `BotDialoguePack-zh-CN/<Type>Dialogue.yaml`，按**节点名**（`Greeting`/`SingleResponse`/`WhatsUp`/`Rare`/`SmackTalk`…）取随机行，支持 `{PLAYER_*}`/`{MAP}` 等占位符。
- **SocialBot 现状意图路由**（`handleDialogueChoice`）：`告别`(`bye/goodbye/cya`) → `组队`(选项4) → 菜单类目(`WhatsUp/Interesting/Rumors`) → 否则 **LLM 自由对话**，LLM 关则回落 `WhatsUp`。**没有**问候/调侃/夸奖/大笑/认同的识别。

### 1.3 已覆盖的关键词（避免重复）

- 组队：`party/team/join/组队/组我/带我/一起/上车/刷怪`
- 跟随：`follow/come/lead/跟我走/跟着我/跟我来/跟着/跟上/走这边/过来/带路/一起走/我带你`
- 练级留驻：`train/grind/station/开打/开干/开始打/开练/开刷/杀怪/打怪/练级/就这里/在这儿/停下/站住…`
- 社交菜单：`whats up/咋样/怎么样/近况/在干嘛`、`interesting/新鲜事/有意思/八卦`、`rumor/传闻/听说/小道消息`、`team/party/组队/一起打/带我/上车`、`bye/goodbye/再见/拜拜/走了/溜了`
- 招募喊话：`party/team/join/group/组队/一起`

## 2. 设计原则与硬约束

1. **子串匹配**：`contains` 无词边界。**禁止**单字/短符号关键词（"哈""牛""菜""6"）进入 `contains` 列表——会吞掉"我在这干啥""料理""6点半"这类正常聊天。
2. **按序判定**：选项顺序 = 优先级。新增意图必须排在有歧义的旧类目**之前**或**之后**并显式说明。
3. **双入口都要接**：`onFirstInteraction`（第一句）与 `handleDialogueChoice`（菜单交互中）都要能识别社交意图，否则玩家"先说你好、再说哈哈"时第二句无人认领。
4. **中英双语**：每类都补 `zh-CN` 别名；英文关键词保持权威、不删减。
5. **不夺功能意图**：调侃/夸奖类不得包含已用于组队/跟随的词（如"带"）。凡重叠，**功能意图优先**。
6. **台词不裸奔占位符**：新台词行要么无 token，要么 token 必须能解析（沿用 `getRandomResolvedLine` 的"解析失败则不发声"纪律）。
7. **默认可关**：社交意图识别属"锦上添花"，加开关（如 `chatter.social_intent`），异常/无台词时**退化为现状**（回 `Greeting`/`WhatsUp`），不引入沉默或报错。

## 3. 意图分类（taxonomy）

按"玩家原话 → 意图 → 台词节点"设计。优先级从高到低（先判更具体、更易误伤的）：

| # | 意图 | 台词节点（新增） | 说明 |
|:--:|---|---|---|
| 1 | 告别 | `Goodbye`（复用） | 已有，大幅扩充词汇 |
| 2 | 组队/求带 | 复用 party 流 | 功能意图，**最高**，不受本方案影响 |
| 3 | 道歉 | `Apology`（新增） | "抱歉""对不起""打扰了" |
| 4 | 感谢 | `Thanks`（新增） | "谢谢""多谢""辛苦了" |
| 5 | 夸奖 | `Praise`（新增） | "厉害""牛逼""大佬""秀" |
| 6 | 鼓励 | `Cheer`（新增） | "加油""冲""你可以的" |
| 7 | 调侃/吐槽 | `Banter`（新增） | "就这""菜""离谱""服了""摆烂" |
| 8 | 惊叹 | `Wow`（新增） | "卧槽""哇塞""好家伙""爷青回" |
| 9 | 大笑 | `Laugh`（新增） | "哈哈""笑死""233""xswl" |
| 10 | 认同 | `Agree`（新增） | "嗯嗯""确实""有道理"+1 |
| 11 | 问候 | `GreetingCommon`（新增，或并入 `Greeting`） | "你好""在吗""早""吃了吗" |
| 12 | 询问 | 复用 `WhatsUp/Interesting/Rumors` | 已有，扩词汇 |
| 13 | 其他 | LLM / `SingleResponse` 兜底 | 现状 |

> 设计取舍：
> - **问候**排在大笑/调侃**之后**，因为"哈哈哈"更常见于纯娱乐反应；但"哈喽/哈罗"是问候整词，**在问候类内特判优先于 Laugh**（见 §6）。
> - **道歉先于感谢**：中文常连说"抱歉谢谢"，先给更少见的道歉回一句更自然。
> - **惊叹与夸奖分列**："卧槽"多为惊讶而非夸，"牛批/厉害"才是夸；分列避免张冠李戴。
> - 若实测冲突，可调序（见 §6）。

## 5B. 人格层：让 bot"像真玩家一样嘴欠"（核心诉求）— ✅ 已实现

> 这是本方案的重心。上文 §4 解决"**听懂**"，本节解决"**回得像人、且嘴欠**"。
> **实现落地**：`Persona` / `SocialPersonaConfig` / `SocialBot` / `SocialLlmPromptBuilder` / `SocialLlmService` + `Banter` 台词节点（中英）。默认档 = 偏喷子（cheeky，65% 回复带刀）。

### 5B.1 现状诊断（为什么现在不够"人味"）

| 机制 | 现状 | 问题 |
|---|---|---|
| 回复风格 | `Greeting`/`SingleResponse`/`WhatsUp` 等 YAML 池 | 台词**偏友善/自述**（"背包又满了""在攒金币"），不是"对着玩家"说 |
| 嘴欠池 | `SmackTalk`（中文 **820 行**，非常嘴欠） | **触发极严**：bot 须高出玩家 **≥15 级** + **25%** 概率 + **每人 5 分钟冷却**；**英文包没有** |
| 挂载时机 | `pickResponseCategory()` 仅作用于 **SINGLE_RESPONSE 型**开局应答 | 30% 的 INTERACTIVE 型、LLM 路径**完全不嘴欠** |
| LLM 提示词 | "Be friendly and **slightly playful**" | 与"嘴欠"方向相反 |
| 目标感 | 多数台词是"自说自话" | 缺少"**对着玩家**"的称呼（老哥/小老弟/兄弟）+ 反问/抬杠 |

### 5B.2 设计：把"嘴欠"做成**人格维度**而非"等级碾压"

引入三个正交维度，每个都从 YAML 取台词，互相可叠加：

1. **人格（Persona）**——bot 的说话底色，预先分派、长期稳定：
   - `TEASE`（嘴欠/毒舌，**目标默认**）、`SARCASTIC`（阴阳怪气）、`CASUAL`（随意）、`HYPE`（网感/梗多）、`CHILL`（佛系）、`FRIENDLY`（温和，保留）。
   - 分派：按 bot id 哈希 → 权重分布（如 `TEASE 40% / CASUAL 20% / HYPE 15% / SARCASTIC 10% / CHILL 10% / FRIENDLY 5%`），**同一 bot 永远同一人格**（稳定 = 像真人）。
2. **语气强度（Tone）**——随关系/情境升降，**不再只看等级差**：
   - 初次见面 → 轻嘴欠；
   - 熟络（`InteractionTracker` 互动次数高）→ **更欠**（真朋友才互相损）；
   - bot 等级高 → 可加重；玩家等级反超 → 收敛；
   - 玩家刚夸它 → 回"嘴硬式谦虚"；玩家刚损它 → **回怼**。
3. **安全阀（Guard）**——嘴欠≠骂人：
   - 复用现有 `smackTalkCooldowns` 思路做**频次阀**（如每玩家 60–120s 一次"重嘴欠"，其余为轻嘴欠）；
   - **人格开关**：`TEASE`/`SARCASTIC` 人格可配置概率，GM 能一键调低或关掉；
   - **红线**：不涉及现实人身攻击、地域/性别/家人、辱骂词；只"损游戏里的事"（装备/等级/手速/宠物/公会/人气）。

### 5B.3 "嘴欠"台词节点（新增，按人格）

新增节点（中英各一套，`zh-CN` 为主力，`en-US` 补一版更轻的）：

| 节点 | 用途 | 中文示例（对**玩家**说） |
|---|---|---|
| `TeaseLight` | 轻嘴欠（默认底色） | 就这就这？/ 你这手速我服了。/ 又是个只会喊口号的。/ 你练了这么久就这？ |
| `TeaseHard` | 重嘴欠（低频+冷却） | 小老弟你这装备我扔了都不捡。/ 你等级还没我一半吧？/ 就你这操作也敢来主城站街？ |
| `TeaseBack` | **被损后回怼** | 急了急了。/ 破防了吧。/ 你自己不也这样？/ 我菜我承认，你呢？ |
| `HumbleBrag` | 被夸后嘴硬 | 过奖过奖，也就比你强一点。/ 没办法，天赋。/ 低调，别夸了。 |
| `Sarcastic` | 阴阳 | 哦，是是是，你说的都对。/ 好厉害哦（棒读）。/ 哈哈哈哈你觉得我会信？ |
| `Hype` | 网感/梗 | 家人们谁懂啊。/ 有一说一。/ 退！退！退！/ 蚌埠住了。 |

> 与 `SmackTalk` 的关系：`SmackTalk` 保留为**"等级碾压"专属加强池**（bot 高等级时的 `TeaseHard` 富矿）；本次新增的按人格节点用于**日常**（不分等级差），让"嘴欠"从"稀有事件"变成"常态底色"。

### 5B.4 挂载点（怎么让每句话都带人味）

`SocialBot` 统一抽一个 `pickReplyCategory(player, intent)`，**所有**回复路径都走它：

```
intent(§4 社交意图) + persona(5B.2) + tone(关系/等级) → 选节点 → getRandomLine
```

| 路径 | 现状 | 改法 |
|---|---|---|
| 开局应答 `appendSingleResponse` | 已用 `pickResponseCategory`（仅等级碾压） | 改为 `pickReplyCategory`：人格 + 轻嘴欠常驻 |
| 交互问候 `appendGreeting` | 只有 `Greeting` | 人格化问候（`Greeting` + 20–40% 概率嘴欠尾巴） |
| 意图回复（§4 新意图） | — | 按 intent 选节点，叠人格 |
| LLM 路径 | "friendly" 提示词 | 提示词注入**当前人格**（"你说话有点嘴欠/阴阳/网感"） |
| `PlayerReaction`（擦肩而过） | 复用 | 人格化 bark（可选） |

### 5B.5 LLM 提示词改造（关键：让 LLM 也"嘴欠"）

`SocialLlmPromptBuilder.systemPrompt` 现在是 "friendly and slightly playful"。改为按人格注入：

```text
You are {name}, a Maple v83 player — not an NPC, not an assistant.
Personality: {persona_描述}      # 如"嘴欠但无恶意，喜欢调侃别人的等级/装备/手速"
Tone now: {tone}                 # 如"和这人聊熟了，可以更欠一点"
Rules:
- 1-2 条短句，像真人打字，可用网络用语（就这/破防/蚌埠住了/退退退）。
- 可以有态度、可以抬杠、可以损，但只损"游戏里的事"，不人身攻击、不带脏话、不涉现实。
- 不主动组队/加buff（交给菜单）。
```

并把每个 bot 的 persona 存进 `SocialChatSessionStore` 的会话头，保证多轮一致。

### 5B.6 反模式（避免"假嘴欠"）

- ❌ **全员同一句**：台词池要够大（每节点 ≥100 行）、且按人格分池，否则"就这就这"复读。
- ❌ **无差别攻击**：对陌生人上来就重嘴欠 = 冒犯；用 `Tone` 分初次/熟络。
- ❌ **嘴欠无回应**：玩家损它必须有 `TeaseBack`，否则"单向输出"露馅。
- ❌ **越界**：任何涉及现实、家人、地域、辱骂的行一律不入池，并在测试里静态扫描拦截。
- ❌ **冷却失控**：`TeaseHard` 必须走频次阀 + 每人冷却，否则高等级 bot 见谁都骂。
- ⚠️ **中英不对等**：`en-US` 也要有嘴欠池（当前 `SmackTalk` 只有中文），否则英文玩家看到的是"哑炮"。

|---|---|---|

## 6. 匹配优先级与冲突规避

判定顺序（`handleDialogueChoice` 与 `onFirstInteraction` 共用一条）：

```
告别 > 组队/求带 > 道歉 > 感谢 > 夸奖 > 鼓励 > 调侃 > 惊叹 > 大笑 > 认同 > 问候 > 询问(whatsUp/interesting/rumors) > 兜底
```

- **功能意图（告别/组队）优先**：任何重叠都让位。
- **夸奖先于调侃**：`6`/`牛` 既可能夸也可能阴阳 → "大佬/厉害"更明确，先夸。
- **惊叹让位明确意图**："离谱/666/好厉害"先被 Banter/Praise 认领，`Wow` 只收无歧义纯惊讶词（"卧槽/哇塞/好家伙"）。
- **大笑 vs 问候**："哈哈"归 Laugh；但 "哈喽/哈罗"是问候整词 → 在**问候类内做整词特判并前置**，避免"哈"字误伤。
- **exact vs contains 双规则**：短符号/缩写（`6/666/233/hhh/88/nb/yyds/xswl/awsl/u1s1/gkd`）走 **exact**（`equalsIgnoreCase` 或去空白/标点后等值）；≥2 汉字走 **contains**。
- **负向排除**：问候类排除含"哈哈"的串（防"哈哈哈"被判问候）；Laugh 类排除"哈喽/哈罗"。
- 每条意图匹配器返回**首个命中**，不再跨类目回退。

## 10. 风险与边界

1. **`contains` 误伤是头号风险**——故严禁单字；短符号走 exact；上线前用真实聊天样本跑一遍（"我升级了""料理""带个头"等）。
2. **优先级一旦定死**，调序要同步改测试；建议在文档留"顺序即语义"的注释。
3. **LLM 路径**：开了 LLM 时自由文本本就走 LLM，本方案的价值在**关 LLM / 兜底**时仍有在国内语境里自然的台词；不改变 LLM 主路径。
4. **别让 SocialBot 变话痨**：新意图只在**玩家主动搭话**时触发（`onFirstInteraction` / `handleDialogueChoice`），**不进**环境闲聊（`BotChatter`/`GrindAmbient`），避免全城 bot 复读"哈哈哈"。
5. **调侃要有分寸**：`Banter` 台词保持"轻量回嘴"，不要变成人身攻击；`SmackTalk` 的等级门槛（`canSmackTalk`）不变。
6. **网络梗时效性**：缩写/梗（`栓Q`/`蚌埠住了`/`退退退`/`老六`）会过气；建议放 `BotMessages-<lang>.yaml` 便于热更，并保留一批"长青"词（哈哈/厉害/加油/谢谢）作为骨架。
7. **量大的代价**：约 400+ 条关键词需要**去重与串扰检查**（同一词不得落在两类 `contains` 里），建议加一个单测：遍历所有意图关键词，断言无交叠、无异类命中（见 §9 第 16 项）。
8. **方言/谐音仅取常用**：如"可不咋的""沙扬娜拉"，避免一次性收太多生僻写法导致维护负担。
9. **"嘴欠"是双刃剑**：能显著提升"像真人"感，但过头就成了骚扰。必须靠 `Persona` 分派（不是所有 bot 都毒舌）+ `Tone` 分级（熟络才重）+ 频次阀 + 安全阀 + 红线静态扫描五道闸；默认档位建议"轻嘴欠为主、重嘴欠偶发"。
10. **人格与"礼貌"不冲突**：`FRIENDLY`/`CHILL` 人格保留，让世界有层次——**不是每个 bot 都欠**，才显得"真玩家"各有性格。
11. **中英对等**：`SmackTalk` 当前仅中文，英文端要做对等嘴欠池，否则语言切换即露馅。
